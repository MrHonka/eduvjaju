## Спринт 1: Подготовка инфраструктуры (Linux)
- **Задача:** Сделать из второго ПК управляемый сервер.
- **Что делаешь:** Ставишь чистый дистрибутив Ubuntu Server (или Debian) на второй ПК. Настраиваешь статический IP-адрес. Связываешь компьютеры по сети. (мы тут)
- **Итог:** Ты заходишь со своего основного ПК на второй сервер по SSH без пароля (по ключам).

## Спринт 2: Упаковка приложения (Docker & База данных)
- **Задача:** Понять, как изолировать процессы.
- **Что делаешь:** Пишешь простейшее веб-приложение (на Python/Go/Node.js) или берешь готовое. Пишешь для него Dockerfile. Собираешь образ.
- **Итог:** Твое приложение запускается в Docker на целевом сервере одной командой и хранит данные в соседнем контейнере с PostgreSQL/MySQL.

## Спринт 3: Автоматизация настройки (Ansible)
- **Задача:** Перестать настраивать сервера руками.
- **Что делаешь:** Пишешь Ansible-плейбук на основном ПК.
- **Итог:** Одной командой Ansible сам устанавливает Docker, обновляет систему и раскатывает нужные утилиты на втором ПК.

## Спринт 4: Развертывание Kubernetes (K8s)
- **Задача:** Запуск оркестратора.
- **Что делаешь:** Поскольку у тебя два ПК, полноценный кластер «из коробки» (где один ПК — это Control Plane, а второй — Worker) может быть избыточен по ресурсам. Мы развернем легковесный K3s или MicroK8s на целевом сервере.
- **Итог:** С основного ПК через утилиту kubectl ты полностью управляешь кластером на втором ПК.

## Спринт 5: Деплой приложения в K8s
- **Задача:** Запуск контейнеров в проде.
- **Что делаешь:** Пишешь манифесты Deployment, Service и Ingress.
- **Итог:** Приложение работает в Kubernetes, автоматически перезапускается при сбоях, а ты заходишь на него через браузер.

## Спринт 6: Конвейер автоматизации (CI/CD)
**Задача:** Код должен сам лететь в кластер при пуше.
**Что делаешь:** Настраиваешь GitHub Actions или self-hosted GitLab Runner на одном из ПК.
**Итог:** Ты меняешь строчку кода в репозитории → срабатывает триггер → собирается новый Docker-образ → обновляется приложение в Kubernetes.
